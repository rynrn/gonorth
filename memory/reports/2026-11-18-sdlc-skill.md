# SDLC — התקנה וסקירה, 18.11.2026

המשתמש ביקש ליצור את SDLC לפי מפרט, לערוך סקירה עצמאית מארבעה תפקידים,
ליצור תרשים ולפתוח PR. לאחר הסקירה אישר גם מיזוג אוטומטי.

רמת הסיכון: L1 לשינויי קוד מקומיים; הפרסום והמיזוג נעשים ב־GitHub בלבד.
מקור האמת: Git, תחת `.claude/skills/sdlc` עם כניסה ל־Codex ב־`.agents/skills/sdlc`.
אין שינוי באתר, ב־WordPress, בנתוני מקומות או בהגדרות שרת.

הסקיל כולל ארבעה workflows, תשעה תפקידי סוכנים, runner של Node עם תור ובדיקת
סכמות, יומן ראיות מקומי, שמירת בדיקות regression בכל סבב, fingerprint של
התוכן ובדיקות merge לאחר CI בשם ידוע ועל ה־commit שאומת.

סקירה: מאתגר חשיבה, ארכיטקט, איש בדיקות קצוות ומציע שיפורים. הפערים תוקנו
ונבדקו בסבב review נוסף. פירוט: [החלטות](../../docs/sdlc-review-2026-11-18.md).
הפעלה: [SDLC](../../docs/SDLC.md). התרשים נוצר ב־ImageGen המובנה.

אימות: `npm --prefix .claude/skills/sdlc run verify`, בדיקת סודות של הריפו,
ו־CI ב־PR. בדיקות transport משתמשות ב־Node חי ובסוכנים מדומים; אין טענה
להשלמת ריצת LLM מלאה במסגרת הבדיקות. הפעולה החיה היחידה היא PR ומיזוגו.

צילום מצב: commit הבסיס של ה־PR. rollback: revert ל־commit המיזוג דרך PR חדש.
ה־helper אינו משנה הגנות ענפים ואינו מפעיל הרשאות bypass. בדיקות client
אינן תחליף ל־required-check rules בשרת; המגבלה מתועדת.

מקורות שנבדקו ב־18.11.2026: מפרט המשתמש, קוד הסקיל, בדיקות regression,
https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request
