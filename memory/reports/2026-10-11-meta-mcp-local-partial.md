# התקנת Meta MCP מקומי — 11.10.2026

סטטוס: **חלקי — השרת מותקן ונטען ב־Codex; יצירת הטוקן והקריאה החיה חסומות בגישה ל־Chrome.**

## תחום והרשאה
בקשת המשתמש מתירה התקנה מקומית, יצירת טוקן לאפליקציית Go North מספר 1074758921991224 עם pages_show_list ו־pages_read_engagement בלבד, ושמירת סודות מחוץ ל־Git. ללא פרסום, מחיקה או מודעות.
רמת שינוי L2 (הגדרת חיבור ותשתית סודות). כותב קנוני: Codex CLI לרישום שרת, קבצים מקומיים להפעלה, Windows DPAPI לשמירת סודות עתידית. לא נערכו חשבון Meta או אתר WordPress.

## מה הושלם
- נבדק config.toml בפועל עם ערכי סודות מוסתרים. analytics-mcp ו־gsc היו קיימים; Meta לא היה מוגדר.
- נוצר שרת GoNorth ייעודי לקריאה בלבד, על בסיס SDK הרשמי של MCP. זה אינו מוצר MCP רשמי של Meta.
- נתיב: C:/Users/avisror/.codex/mcp/gonorth-meta-readonly/.
- SDK 1.32.1 ו־zod 4.6.5 מותקנים בגרסאות נעולות עם package-lock, ללא סקריפטי התקנה.
- רישום: gonorth-meta-readonly, הפעלה באמצעות Node מקומי, שישה כלי קריאה.
- העתק תצורה לפני השינוי נשמר בתיקיית ההתקנה המוגנת בשם config.before-meta.toml, מחוץ ל־Git.
- ACL התיקייה: המשתמש avisror ו־SYSTEM בלבד; ירושה מהורה בוטלה.
- מנגנון שמירת טוקן משתמש ב־DPAPI. הטוקן המיועד לא נשמר בתצורת Codex, בארגומנטים, ב־Git או בלוגים. בפועל עדיין אין user-token.dpapi.
- כל בקשת תוכן מחייבת Page ID מאושר מקומית ואימות טוקן משתמש: App ID, תוקף ושתי הרשאות הקריאה בלבד, בתוספת public_profile הבסיסית אם קיימת.
- אין כלי API חופשי; רק GET ל־graph.facebook.com, בלי מעבר להפניות. טוקני דפים בזיכרון בלבד.
- הוכנה הנחיית המשך ושחזור ב־README.md בתיקיית ההתקנה.

## ראיות
- שרת Meta הופיע במלאי הכלים של השיחה עצמה.
- קריאת MCP אמיתית ל־connection_status החזירה token_stored=false, read_only=true, App ID הנכון, ושתי ההרשאות הנכונות.
- קריאת verify_connection דרך MCP החזירה TOKEN_NOT_CONFIGURED. זו אינה בדיקה חיה מוצלחת מול Meta.
- בדיקת SDK stdio: initialize, tools/list ו־tools/call עברו; שישה כלים עם readOnlyHint וללא destructiveHint; stderr ריק.
- חמישה תרחישי אבטחה עברו: טוקן שגוי/פג/עודף הרשאות, GET בלבד, צמצום פלט, דפים לא מורשים ופוסטים מדף אחר, שגיאות מסוננות ו־pagination ללא מעקב אחרי next URL.
- בדיקת DPAPI עם נתון דמה בלבד עברה: הצפנה/פענוח, אי־שמירת plaintext, שמירה שקטה ומניעת דריסה. נתון הדמה נמחק.
- npm audit: אפס חולשות מדווחות בזמן הבדיקה.
- TOML parser השווה את analytics-mcp ו־gsc לגיבוי: זהות סמנטית מלאה. סעיף node_repl המנוהל בידי סביבת הדפדפן השתנה במהלך בדיקות האיפוס; לא בוצע שחזור גורף.
- תקלה ראשונית בשמירת סוד נבעה מחיפוש מודולי PowerShell; עוזר ההצפנה הוגבל למודולים המובנים של Windows PowerShell. RemoteSigned חל על תהליך העוזר בלבד; מדיניות המשתמש/המחשב לא שונתה.

## חסם והשלמה
כלי Chrome נכשל לפני גישה לכרטיסיות עם windows sandbox failed: helper_unknown_error: setup refresh had errors. איפוס וניסיון נוסף לא תיקנו זאת. קריאת קבצים והתקנה הצליחו במסלול הרצה מורשה מחוץ ל־sandbox. לא התקבלה שגיאה מ־Meta ולא נוצר טוקן.

הצעד הנדרש: סגירה מלאה ופתיחה מחדש של Codex כניסיון לשחזור סביבת כלי Chrome, ואז המשך השיחה עם כרטיסיית Graph API Explorer פתוחה. אין הוכחה שהפעלה מחדש לבדה תפתור את התקלה. לא נדרש אישור נוסף לשתי ההרשאות שכבר אושרו, ואין להעביר טוקן בצ'אט.

לאחר התאוששות: לבדוק באפליקציה את App ID וההרשאות, ליצור User Access Token ולשמור בצינור מאובטח באמצעות vault.ps1; להריץ verify_connection ו־list_pages; לזהות בוודאות את דף GoNorth; להוסיף את מזההו ל־settings.json; לרענן את שרת MCP; לקרוא פרטי דף, פוסט אמיתי וספירות מעורבות. אין להוסיף הרשאות כדי לעקוף כשל. גרסת API v25.0 דורשת אימות בהשלמה; דפי Meta הרשמיים לא היו נגישים בכלי המחקר.

השרת עצמו כבר נטען בלי הפעלה מחדש של Codex. רענון שרת נדרש אחרי שינוי רשימת Page IDs, שנקראת בעת האתחול. הפעלה מחדש של האפליקציה מוצעת כאן לתקלה בכלי Chrome.
