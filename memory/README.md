# זיכרון העבודה של GoNorth

התחילו ב־[מצב נוכחי](current-status.md), בדוח האחרון וב־[החלטות](decisions.md), ואז ב־Issue הרלוונטי.

- `reports/`: דוחות מתוארכים שאינם נדרסים. ריצה נוספת באותו יום מקבלת סיומת שעה.
- `data/`: נתוני מקור ציבוריים/מצומצמים עם מקור ומועד. אין סודות או פרטים אישיים.
- `plans/`: תוכניות, אצוות, קישורי משימות וחסמים.
- `drafts/`: תוכן מוצע ומקורות. טיוטה אינה פרסום.
- `scripts/`: כלי איסוף חוזרים; אין שינוי באתר.
- דוחות קודמים נשארים ב־`../audits/`.

## שיטת עבודה

כל מדד מסומן כנוכחי, היסטורי או לא זמין. חסר אינו אפס. בסוף סבב מעדכנים מצב, החלטות וקישורי משימות. אין לדרוס snapshots. תיקון לדוח שנחתם נרשם בדוח המשך.

Search Console: אותו נכס, סוג חיפוש, חתך ותקופות שוות של 28 ימים מלאים; בדיקת זמינות נתונים לפני קביעת תאריך סיום. יש לציין עונתיות ושינויים באוכלוסיית העמודים. CTR מצרפי מחושב מסכומי קליקים וחשיפות; לא ממוצע פשוט. אין לסכם שורות שאילתות כאילו הן סך הנכס, בגלל מידע אנונימי ומגבלות שורות. שינויים באתר ותוצאות אורגניות מדווחים בנפרד.

## איסוף ביקורת חוזרת

`pwsh -File memory/scripts/collect-place-audit.ps1`

הכלי אוסף את כל העמודים המפורסמים דרך GeoDirectory API ושומר JSON עם תאריך. הוא אינו מאמת את העובדות אצל העסקים ואינו משנה `practical_checked_at`. ספירת תוכן: HTML עריכתי ללא תגיות, פענוח entities, כיווץ רווחים. סף דלילות: פחות מ־500 תווים, כולל ריקים.

## חגים

משימת־אב [#48](https://github.com/rynrn/gonorth/issues/48), יתרת 2026 [#49](https://github.com/rynrn/gonorth/issues/49), תכנון 2027 [#50](https://github.com/rynrn/gonorth/issues/50).

לפני סגירת כל משימת חג מ־2027: לחפש משימה לשנה הבאה בכל המצבים, ליצור רק אם חסרה, לקשר בשני הכיוונים ולהעתיק את ההוראה. משימת השנה הבאה ממתינה לסקירת נובמבר–דצמבר. אין אוטומציה מתוזמנת.


## עסקים סגורים

דיווח על סגירה אינו הוראה למחוק עמוד. ברירת המחדל היא להשאיר את כתובת העמוד מפורסמת ומאונדקסת עם HTTP 200, להציג סטטוס ברור ותאריך בדיקה, להסיר שעות, טלפון, ניווט וסכמה שמציגים עסק פעיל, ולהוסיף חלופות רלוונטיות. הפניית 301 מתאימה רק ליורש אמיתי או לעמוד חלופי קרוב מאוד. מחיקה, טיוטה, private או 404/410 דורשים בדיקת תנועה, קישורים ואינדוקס, תיעוד סיבה והוראה מפורשת מהמשתמש.

## אימות מידע משתנה

המערכת נמצאת ב־`../place-facts/`. לפני שינוי סטטוס עסק, שעות, טלפון, כתובת או אתר, מייצאים או מגישים תוצאה דרך `place-facts/scripts/place-facts.py`. סוכנים אינם כותבים SQL ישירות. רק שינוי שעבר ביקורת יכול להסתנכרן ל־WordPress.
