# גיבוי מקומי יחיד ותזכורת חודשית — GoNorth

עודכן: 2026-10-02. מדיניות שאושרה בידי המשתמש; מחליפה את תכנון הגיבוי האוטומטי בשרת.

## מה נשמר
עותק גיבוי תקין אחד במחשב:
C:/dev/gonorth/backups/monthly/current/

בתיקייה שני קבצים: site.zip וה-manifest.json שמפרט מועד יצירה, שמות קבצים ו-SHA-256.
הנתונים מוחרגים מ-Git ומוגנים בהרשאות Windows למשתמש הנוכחי, SYSTEM ומנהלים.
אין להעביר גיבוי או את תכולתו ל-GitHub, לדוחות ציבוריים או לצ'אט.

זיכרון מצב: memory/backup-status.json. כולל את מועד איסוף ה-snapshot, מועד האריזה, נתיב, גודל, checksum, מועד אימות, מועד בדיקת הסוכן ומועד בקשת החידוש. זהו קובץ תיעוד קטן, לא גיבוי נוסף.
דוחות מתוארכים נשמרים ב-memory/reports; אין לדרוס היסטוריה.

## התכולה
- database.sql — יצוא מלא של מסד הנתונים.
- כל wp-content, לרבות תוספים, תבניות ומדיה.
- wp-config.php וקובצי הגדרה בשורש האתר, אם קיימים.
- תצורות Nginx ו-PHP קריאות הרלוונטיות לאתר.
- snapshot.json — זמן איסוף, גרסת WordPress, מקורות ומגבלות.

זהו גיבוי יישום. קובצי ליבת WordPress, מערכת ההפעלה ומפתחות TLS אינם כלולים. בשחזור מתקינים את גרסת WordPress המתועדת ומנפיקים תעודות מחדש. יצוא DB טרנזקציוני והעתקת קבצים אינם snapshot אטומי של השרת כולו. בדיקת שלמות ZIP אינה בדיקת ייבוא SQL; אין לדווח שבוצע שחזור DB אם לא נעשה בפועל.

## חידוש לאחר אישור
1. קראו את הסקיל והזיכרון ובדקו שלא קיימות ריצות מקבילות או תיקיות new/previous שלא טופלו. בדקו מקום פנוי במחשב ובשרת. לא משנים הרשאות root.
2. התחברו ב-ssh gonorth. העלו את collect_server.py ואת monthly_backup.py מתיקיית scripts של הסקיל ל-/home/claude. בדקו תצורה מקומית בלי להדפיס סודות.
3. הפעילו python3 /home/claude/collect_server.py. הוא מכין תיקייה פרטית 0700 ב-/home/claude/.local/share/gonorth-snapshot-transfer, מוודא טבלאות InnoDB, מייצא DB, מעתיק רכיבים ובודק עותקים. אין החרגה שקטה של מדיה או מטמון.
4. הכלי אורז ומאמת את הגיבוי תחת package/current בתוך תיקיית העבודה. אם יצוא, קובץ או תצורה נדרשת חסרים — עוצרים. הישן המקומי נשאר ללא שינוי.
5. מורידים באמצעות scp רק את site.zip ואת manifest.json אל C:/dev/gonorth/backups/monthly/new/. אין להחליף קובץ ב-current במהלך ההורדה.
6. אחרי שההעברה הסתיימה בהצלחה:
```powershell
python .agents/skills/gn-monthly-backup/scripts/install_local.py --approved-refresh
python .agents/skills/gn-monthly-backup/scripts/monthly_backup.py verify C:/dev/gonorth/backups/monthly/current
```
ההפעלה עם --approved-refresh מותרת רק אחרי אישור המשתמש. הכלי מאמת את checksum של הארכיון וכל קובץ, שומר את הישן זמנית ב-previous, מקדם את החדש, מאמת שוב, ורק אז מסיר את previous.
7. כתבו בזיכרון רק מועדים ונתונים שנקראו מ-snapshot.json ומהמניפסט בפועל. אפסו last_reminder_at ברענון מוצלח, תעדו last_verified_at ואת תוצאת הבדיקה. אין לשנות snapshot_collected_at בזמן בדיקה בלבד.
8. לאחר אימות העותק המקומי, נקו את תיקיית האיסוף והאריזה המדויקת בשרת. לפני מחיקה רקורסיבית אמתו realpath, בעלות ושהיעד הוא בדיוק /home/claude/.local/share/gonorth-snapshot-transfer, ואמתו ש-checksum המקומי תואם. בכשל אל תמחקו את המקור היחיד.
9. בסיום מוצלח נשאר current אחד במחשב, ללא עותקי עבודה נוספים. בזמן ההעברה ייתכנו זמנית שני עותקים; בכשל שומרים אותם לבירור.

## תקלה
new, previous או .lock מריצה שנקטעה מחייבים בדיקה לפני ריצה נוספת. אין להסיר נעילה בלי לוודא שאין תהליך פעיל.
כשל לפני קידום שומר את current הישן. כשל בקידום מנסה להחזיר previous ל-current. כשל בבדיקה אחרי קידום או במחיקה משאיר את העותקים לבדיקה ומדווח כשל.
אין למחוק גיבויים אחרים, snapshots היסטוריים או גיבויי UpdraftPlus במסגרת ההחלפה.
