## המבנה שסוכם

ארבעה workflows נשארו מקור האמת ללולאות. runner יחיד מריץ אותם ושולט בתור,
מזהי בקשות, timeout ותוצאות סופיות. ה־host מפעיל סוכנים עצמאיים, אוכף הרשאות,
מציג שאלות ומבצע Git ופרסום באישור. אין פרשנות ידנית של JavaScript.
בעקבות בקשת המשתמש ואישורו נוסף מיזוג אוטומטי דרך helper ייעודי, לאחר בדיקות
CI בשמות ידועים ועל commit מוגדר, ללא עקיפת הגנות GitHub.

כל סבב validation מריץ את הבדיקות שנבחרו ואת בדיקות ההוכחה מהבנייה, בודק
את מלוא השינוי, ומשווה fingerprint לפני ואחרי. שינוי בזמן review פוסל את
הראיות הירוקות. ממצאים שהופרכו נבדקים מחדש לאחר עריכות. מתן אישור לסיכון
מוגבל לממצאי תכנון; ממצאי validation חייבים להיפתר או להיות מופרכים בראיות.

הפלאגין כולל בדיקות וכלי אימות בתוך תיקייתו כדי שאפשר יהיה להעבירו לריפו
קיים ללא החלפת package.json או README של אותו ריפו. הגדרות בדיקה של הפרויקט
נוצרות ב־init בהתאם לכלים שלו; בדיקות הפלאגין אינן תחליף לבדיקות האתר.

## ראיות ומגבלות

`npm --prefix .claude/skills/sdlc run verify` בודק מבנה, קישורים, JSON, תחביר
ו־regressions. בדיקות transport מפעילות תהליך runner אמיתי עם host מדומה.
בדיקות Git משתמשות בריפוזיטוריז זמניים. אין טענה שנבדקה ריצת LLM מלאה עד PR.
תוצאת האימות הסופית: 86 בדיקות עברו; 9 נקודות כניסה עברו את quick_validate
של skill-creator. בדיקות ה־runner כוללות תהליך חי, תור, null, ניתוק ו־timeout.
ה־hook הוא guard נגד טעויות; הגנת ענפים בשרת ואכיפת כלים ב־host עדיין נדרשות.

התרשים נוצר בכלי ImageGen המובנה ונבדק חזותית; הלולאה תוקנה להיות מחוברת
ל־validation, והגרסה העדכנית מציגה מיזוג אוטומטי אחרי CI בעקבות אישור המשתמש.
הפרומפט נמצא ב־sdlc-image-prompt.txt.

ב־review נוסף על המיזוג נסגרו גם התאמה לריפו origin המקומי, דרישת בדיקות CI
בשמות ידועים, עצירה בכשל סופי, רענון מצב PR לפני הפעולה והצמדת בקשת המיזוג
ל־SHA. המיזוג מיידי לאחר ההמתנה ב־host; אין הרשמה מתמשכת שעלולה למזג commit עתידי.

שחזור מקומי: לשמור עותק של החבילה הקודמת לפני החלפתה; ב־Git ניתן לשחזר את
תיקיות SDLC והמסמכים מה־commit הקודם. אין שינוי ב־WordPress או בנתוני האתר.
